# Branding documentation

## Findings and plan

The repository uses `Espejismo` as the project name in the README and
positioning guide, while package and binary identifiers use lowercase names
such as `espejismo-local` and `espejismo-remote`. No approved graphical logo or
logo source asset is present. The positioning guide also sets important limits
on product claims: the core protocol does not impersonate other protocols and
the project does not claim invisibility.

Added `docs/BRANDING.md` to establish exact prose casing, preserve lowercase
technical identifiers, describe the two component names, and specify a
text-only wordmark until an approved graphic asset exists. The guide explicitly
prohibits unsupported camouflage and invisibility claims. This clarifies future
documentation and visual work without changing project identity, assets,
product positioning, or runtime behavior. Expected benefit: fewer inconsistent
name and logo treatments across future materials; no runtime or performance
change is expected.

## Validation and outcome

- Reviewed `README.md`, `docs/POSITIONING.md`, and
  `docs/DOCUMENTATION_STYLE.md` as the canonical naming, positioning, and
  documentation references.
- Confirmed no existing graphical logo or branding guide is present in the
  repository.
- Documentation-only change; no code behavior changed, so build and runtime
  tests are not applicable.
- Outcome: naming/logo guidance is documented and consistent with the existing
  positioning. No measurable performance change is expected.
